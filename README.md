# GitSpidy v0.1.0

gitspidy показывает статистику истории локального git-репозитория прямо в терминале

для работы нужен python 3.11+ и установленный git, сторонние библиотеки не требуются

## установка

```bash
git clone <URL-репозитория>
cd gitspidy
python --version
git --version
```

все команды желательно запускать из корневой директории проекта

если нужно запустить gitspidy из другого каталога, можно добавить путь к проекту в `PYTHONPATH`

## использование

```bash
python -m gitspidy
python -m gitspidy scan .
python -m gitspidy scan . --author joost
python -m gitspidy scan . --date 2026-10-30
python -m gitspidy scan . --author joost --date 2026-10-30
python -m gitspidy scan --help
```

`scan PATH` принимает путь к локальному git-репозиторию

`--author` позволяет фильтровать коммиты по имени автора, поддерживает частичное совпадение без учёта регистра

`--date` принимает конкретную дату в формате `YYYY-MM-DD`

фильтры можно комбинировать, вся статистика будет пересчитываться только по подходящим коммитам

при использовании `--date` дополнительно выводится список коммитов за выбранный день

## как работает

история получается через `git log --all`, учитываются все уникальные коммиты из локально доступных ссылок git, ничего из интернета не загружается

для анализа дат используется время автора и часовой пояс, записанный в самом коммите

активность по дням и часам рассчитывается по локальному времени каждого коммита

авторы определяются по точному имени, то есть `Joost` и `joost` будут считаться разными людьми

если несколько дней или часов имеют одинаковую максимальную активность, выбирается самый ранний

первый и последний коммиты определяются по абсолютному времени авторской даты

## обработка ошибок

если репозиторий пустой или фильтры ничего не нашли, все количественные показатели будут равны `0`, остальные значения отображаются как `—`

также выводится сообщение `Коммиты не найдены`

в этом случае программа завершается с кодом `0`, поскольку ошибки как таковой нет

если указан неправильный путь, директория не является git-репозиторием или git не удалось запустить, выводится понятная ошибка без traceback, код завершения `1`

если ошибка связана с аргументами командной строки, код завершения `2`

## тестирование

для тестов используется стандартный `unittest`

```bash
python -m unittest discover -s tests
```

тесты автоматически создают временные git-репозитории, проверяют работу анализатора и не затрагивают пользовательские данные

## структура проекта

```text
gitspidy/
├── gitspidy/
│   ├── __init__.py
│   ├── __main__.py
│   ├── core.py
│   └── cli.py
├── tests/
│   └── test_core.py
├── README.md
└── .gitignore
```

`core.py` отвечает за получение истории коммитов, фильтрацию и расчёт статистики

`cli.py` обрабатывает аргументы командной строки и формирует текстовый отчёт

`__main__.py` используется для запуска через `python -m gitspidy`

`test_core.py` содержит автоматические тесты анализатора
